# Runtime dependencies

The repository owns the source packages under `src/packages`. The authored UI and weapon-model contents remain Studio-only by design and are not expected to be generated by Rojo.

## ReplicatedStorage.packages

The project currently vendors:

| Module | Used by | Purpose |
| --- | --- | --- |
| `Trove` | controllers, services, tests | Resource/lifecycle ownership |
| `Signal` | controllers and services | In-process events |
| `ShapecastHitbox` | client combat | Weapon hitbox sampling |
| `TestEZ` | tests only | Studio test runner |

These package sources are mapped into `ReplicatedStorage.packages` from `src/packages` by `default.project.json`.

`TestEZ` is only needed for `tests/`; it is not a production gameplay dependency.

## ReplicatedStorage.ui

Client code expects Studio-authored UI templates:

- `WeaponMenu`: a GUI template containing `GuiButton` descendants with a string `WeaponId` attribute. A descendant named `Selection` should be a `GuiObject` used as the selected-state indicator.
- `Hitmarker`: a GUI template containing a descendant named `Hitmarker` that is a `GuiObject`.

These assets intentionally remain Studio-only and are not part of the Rojo source tree.

## ServerStorage.weapon_models

Weapon templates are Studio-authored and intentionally server-only. `WeaponService` reads them from `ServerStorage.weapon_models` and clones the selected model into the player's character.

Required built-in templates:

- `Fists`: `BasePart` descendants named `RightFist` and `LeftFist`; each hitbox should contain an `Attachment` tagged `Hitpoint`.
- `Katana`: a `BasePart` descendant named `Mesh`; the hitbox should contain an `Attachment` tagged `Hitpoint`.

Each template must match the weapon definition in `src/shared/weapons/*.lua`.

Keeping templates in `ServerStorage` prevents clients from reading the source models before they are attached to a character.

## World contract

The server registers the `Climbable` collision group during startup. Map parts that participate in climbable traversal should use the `Climbable` collision group and/or the `Climbable` CollectionService tag expected by the parkour query code.

## Character contract

The project requires R6. Weapon definitions use R6 body-part names (`Right Arm` and `Left Arm`), and `CharacterController` rejects non-R6 Humanoids at runtime.

## Source/runtime boundary

Rojo can build the code and vendored package tree directly from this repository. UI and weapon models are deliberate Studio-side authoring contracts rather than missing source dependencies.
